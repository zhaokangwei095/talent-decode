## 重新部署

当前用 CLI 直接推送的方式（未启用 GitHub 自动部署，原因见下文）：

```powershell
# 需要先设置家目录，绕开本机 AppData 的 rename 限制
$env:XDG_DATA_HOME="C:\Users\Rv\Documents\.vercel-cli-data"
vercel --prod --yes
```

## 为什么用 `XDG_DATA_HOME`

本机 `AppData\Roaming` 与 `AppData\Local` 目录下**所有** rename 操作都返回 `EXDEV: cross-device link not permitted`
（不是 Vercel 的问题，Node 原生 `fs.renameSync` 在该路径下同样失败，推测是同步/管控软件接管了这两个目录）。

Vercel CLI 写配置用的是"临时文件 + rename"，因此默认路径必然失败。把它指到 `C:\Users\Rv\Documents` 下即可：

```powershell
$env:XDG_DATA_HOME="C:\Users\Rv\Documents\.vercel-cli-data"
```

同一原因下，`Documents`、`Desktop`、`Temp` 均可正常 rename，其他盘符未测试。

## 未启用 GitHub 自动部署

`vercel git connect` 报 `Failed to connect ... to project`。原因是 **Vercel 账号没有获得该 GitHub 仓库的访问授权**
（Vercel 的 GitHub 集成需要在网页端确认仓库范围，CLI 无法代为授权）。

如需开启"push 即自动部署"，在浏览器里操作一次：

1. 打开 https://vercel.com/dashboard → 右上角头像 → Settings → Integrations → GitHub
2. 确认已连接 `zhaokangwei095` 账号，并勾选 `talent-decode` 仓库（或选 All repositories）
3. 回到项目 https://vercel.com/zhaokangwei095s-projects/talent-decode/settings/git
4. 点 Connect Repository，选 `zhaokangwei095/talent-decode`

之后每次 `git push origin main` 会自动触发生产部署。注意自动部署走 Git 仓库内容，
会遵循 `.vercelignore`——所以本文件的 `.vercelignore` 排除了 `node_modules`、`shots`、
`tools`、`docs`、`data-source`，只保留 `index.html`、`assets/`、`data/`、`vercel.json`。

## `vercel.json` 做了什么

- `cleanUrls`：`/index.html` 与 `/` 归一。
- 字体目录设置一年不可变缓存（文件名含内容哈希之外的子集标识，长期不变）。
- 全站安全响应头：`nosniff`、`SAMEORIGIN`、`strict-origin-when-cross-origin`、最小化 `Permissions-Policy`。
